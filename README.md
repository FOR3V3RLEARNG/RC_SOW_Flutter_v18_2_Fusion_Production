# RC SOW Connected Flutter

Production-oriented Flutter reconstruction of the supplied Stitch screen system for Red Cross shelter/roof-repair operations.

The application consolidates 163 visual variants into 35 canonical, connected product screens. Every workflow resolves to the same selected house and updates shared lifecycle, evidence, inventory, notification, work-log, sync and audit state.

## What is connected

- Authentication entry, responsive five-destination shell and role/parish context
- Dashboard → Scope → Control → Houses → More navigation
- Scope House → Roof → Print → Files stepper
- Beneficiary lookup and house auto-fill
- Roof type and dimension drafting with a responsive CustomPainter canvas
- Duplicate-safe New Control creation
- House Command lifecycle, blockers, readiness and Smart Next Action
- Work Plan, Daily Site Log, Site Visit, Material and Consumable forms
- Document and Monitoring checklists
- Inventory BOQ / Delivered / Additions / Leftovers reconciliation
- Completion readiness, final inspection and Payment 46/31/23 allocation
- Evidence, activity history, notifications, users online and messages
- Work Logs, operational analytics, map, settings and accessibility
- Admin access/privileges, template versioning and Gmail compose UI
- Offline queue semantics and user-readable recovery messages

## Run

This source intentionally keeps platform scaffolding generated by the installed Flutter version. From the project root:

```bash
flutter create --platforms=android,web --project-name=rc_sow_connected .
flutter pub get
flutter analyze
flutter test
flutter run
```

Or run `bash tool/bootstrap_and_verify.sh`.

## Architecture

- `lib/core/models.dart` — house, lifecycle, inventory, evidence and collaboration contracts
- `lib/core/app_state.dart` — connected state, transitions, audit and offline queue
- `lib/core/widgets.dart` — RC SOW design-system components
- `lib/screens/` — responsive canonical screens and operational workflows
- `test/` — state, route and entry-journey contracts
- `docs/ROUTE_MATRIX.md` — canonical screen/route coverage
- `docs/BACKEND_CONTRACT.md` — production integration boundary
- `supabase/migrations/` — optional protected schema starter
- `design_reference/` — original Stitch assets retained for visual comparison

## Production service boundary

The delivered source is fully interactive using a deterministic in-memory repository so it runs without secrets. Real Google OAuth, Supabase persistence/storage/realtime, Gmail delivery, map tiles, camera capture, PDF/XLSX generation and push notifications require organization-owned credentials and deployment decisions. They are not falsely simulated as completed network integrations. The included backend contract and migration define the intended relationships and security boundary.

No secret, service key or production credential is stored in this project.
